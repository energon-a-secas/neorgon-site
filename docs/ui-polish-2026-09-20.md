# Neorgon UI polish: Antenne and catalog

September 20, 2026. Implementation and validation snapshot recorded before release.
Deployment status is tracked in GitHub Pages and the release commit history.

The brief was to improve the page's feel, especially the Antenne popup and story
list, while keeping Neorgon's existing tone. The result keeps the dark backdrop,
Avenir typography, constellation, and tool colors. It changes the news presentation
and adds a little more separation to the catalog.

## What changed

Antenne now renders the latest three valid stories directly from the feed. The
previous implementation fetched that feed and then loaded another page in an
iframe. The native list uses the hub's typography and local catalog artwork,
with a package badge for launches, a sparkle for features, a plus for fixes, and
a document for notes. Each type also has a written label. The newest story gets
a two-line summary; full stories remain one link away.

The popup has a thin border and a dark, opaque surface in place of the silver
frame. Its artwork is static. GIFs remain in the existing opt-in card previews,
where their detail is readable. Multi-tool stories use the first matching catalog
link. A missing match falls back to the satellite; no remote favicon service is
involved. Shared hosts such as GitHub require a matching path, so an unrelated
repository does not inherit another tool's icon.

Dismissal leaves a labeled Antenne dock. Reopening focuses the close button;
close and Escape return focus to the dock, including Safari's pointer-click
case. Automatic opening does not steal focus. Below 900px, the popup is hidden;
short desktop viewports can scroll its contents. Reduced motion disables its
entrance and arrow transitions.

The saved edition includes story IDs and dates, so a new story on the same day
can reopen the bulletin. This replaces the date-only watermark. A legacy
watermark causes one reopening after upgrade; subsequent dismissals use the new
format. Empty or invalid feeds render no popup, and failed fetches leave the
catalog usable. Feed strings are inserted with `textContent` and story IDs are
URL-encoded. Optional image URLs in feed data are never used.

Catalog groups now have 32px spacing, up from 24px, and the grid has 14px gaps,
up from 11px. Fine rules extend category headings. Card borders inherit a small
amount of the tool accent. Keyboard focus gets the same background wash as hover.
Saved, pinned, archived, and alternate-background styles keep their overrides.

The default Python interpreter was too old for the existing icon checker. Using
the installed Homebrew Python allowed the unchanged checker to run.

Browser tests use controlled feed responses. WebKit's HTTP harness removes only
`upgrade-insecure-requests` from the served document response: WebKit otherwise
upgrades localhost assets to TLS, which the local server does not serve. The
production HTML is unchanged by that accommodation. These tests establish UI
behavior, not production TLS or CORS behavior.

The initial deck export passed density validation but its screenshot slides
overflowed. The deck build script adds a height bound to exported images. Geometry
and image loading are checked against the rendered HTML, not inferred from the
validator. The export checker ran, but its file checks target PPTX; PDF verification used PDFKit and a rendered page inspection. The source YAML retains speaker notes. The PDF and HTML use Marp's
flat theme; no pattern textures were authored.

## Remaining limits

- Deployment and a production-origin feed/CORS smoke check remain open.
- Unsupported future story kinds are skipped until the small renderer is updated.
- Multi-tool stories show one icon, not a composite of every destination.
- Preview lint still reports six coverage gaps and fifteen single-frame GIFs.
  Those existing assets were not re-recorded in this pass.
- No performance, task-completion, accessibility certification, or model benchmark
  is claimed. Screen-reader behavior was not manually tested.
